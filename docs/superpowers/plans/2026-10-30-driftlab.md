# Statistical DriftLab Implementation Plan

> **For agentic workers:** Execute natively with superpowers:executing-plans and test-driven-development. User requested autonomous execution, so no plan approval pause.

**Goal:** Compare explicit retained outbox event-index windows using reproducible, currency-isolated distribution effects.

**Architecture:** One bounded PostgreSQL repeatable-read read-only snapshot supplies two disjoint inclusive identity ranges. Pure deterministic statistics produce a frozen typed report with evidence hashes. Authenticated API and HTTP CLI expose this without replaying, acknowledging or changing source/projection state.

**Tech Stack:** Existing Python, Pydantic/FastAPI, Psycopg; standard-library statistics/HTTP; no added dependencies.

**Spec:** Parent task instruction: substantive Statistical DriftLab using actual retained CDC evidence; rigorous windows, metrics, provenance, safe bounds, synthetic evaluation and native runtime verification.

## Global Constraints

- Work in fluxlake only; preserve runtime/dependency pins, public synthetic demo, existing features and workflows.
- Identity allocation order is not commit order or a temporal window. A later run may see late commits in the same range.
- Analyze insert/update events, not current entity population; exclude and count tombstones. Correlated revisions prevent IID inference.
- No p-values, hypothesis rejection or multiple-test significance claims; effect thresholds are descriptive operational rules.
- At most 2000 identity positions per window, 4000 rows total, 32 currencies, 64 KiB per event, 4 MiB total payload, 5-second SQL timeout, 2-second lock timeout.
- Request bodies at most 4096 bytes, strict finite typed JSON; redact input and database errors.

## Review Focus

- Currency composition can change without within-currency amount changes: test separate currency JS and per-currency isolation.
- Ties/constant distributions can collapse quantile bins: test integer-safe KS and fixed baseline support/tails.
- Missing/late/pruned events cannot imply complete history: test gaps and concurrent lower identity commit.
- Boolean/coerced scalar/NaN values must fail closed: strict request and event validation tests.
- Read-only source transaction and no refresh must hold in request mode: actual PostgreSQL and API state/ack checks.
